Where Am I?

A photorealistic 3D "guess the location" game — app map & take-home guide.

What it is

You drop into a real, flyable 3D place (Google Photorealistic 3D Tiles), look around for clues, and click a small corner world map (Leaflet) to drop one locking guess. The game shows how far off you were in kilometers, reveals the true spot, lingers ~5 seconds, then moves to the next place — looping forever. Nothing is saved; a refresh starts over.

Three main pieces: a 3D world view, a corner guess map, and a small pure game-state core that scores and advances rounds.

One action, end to end

What happens when you drop a pin:

You click the mapGuessMap.jsx — captures the click, reports lat/lng
→
Score itApp.jsx calls placeGuess() in gameState.js, which uses haversineKm()
→
You see the resultScoreboard.jsx shows the distance; the true marker appears on the map
→
Next place~5s timer in App.jsx calls advance() — wraps to the first after the last

Where things live (route)

  1. src/lib/gameState.js — the pure heart of the game. placeGuess(), advance(), isLocked(). No React, no DOM — this is what the tests exercise.
  2. src/lib/distance.js — haversineKm(), the great-circle distance used for scoring.
  3. src/App.jsx — holds the state, wires the three components together, and runs the ~5s reveal timer.
  4. src/components/ — World3D.jsx (Google tiles), GuessMap.jsx (Leaflet), Scoreboard.jsx (the overlay).
  5. src/data/locations.js — the hand-picked list: camera start + true coordinates per place.

To change this, start here

  • Add or swap locations → src/data/locations.js. Tune each camera so the landmark frames well; set answer to the true lat/lng.
  • Change the reveal duration → REVEAL_LINGER_MS at the top of src/App.jsx.
  • Restyle the frame (colors, type, panels) → src/styles/app.css (the :root palette variables).
  • Change scoring units/format → src/components/Scoreboard.jsx.
  • Enable the 3D world → put a Google Maps key in .env as VITE_GOOGLE_MAPS_API_KEY (Map Tiles API enabled).

A practice to reuse

Push testable logic to the edge, away from what you can't test.

The 3D tiles layer depends on a live Google key and real rendering, so it can't be meaningfully unit-tested. Instead of giving up on coverage, all the game rules were pulled into a pure module (src/lib/gameState.js) with no DOM or network. That's why tests/gameState.test.js can assert "wraps back to the first location after the last" — your PRD's loop decision as an executable check that runs in milliseconds — while the inherently-visual 3D view is honestly left to a manual smoke test.

Next time you build with an agent against an external service, decide early what is deterministic (and test it hard) versus what is genuinely external (and verify it by hand). It's what makes agent-written code trustworthy end to end.
